面必过：全量启动指南
====================

适用目录：仓库根目录。本指南只记录可从当前 `env_example`、`docker-compose.yml`、
`backend/pyproject.toml` 和启动脚本核实的操作；业务背景见 `docs/knowledge.md`，
目录与调用关系请使用 CodeGraph 查询。

推荐模式：Docker Compose 全容器启动。
该模式会启动 PostgreSQL + pgvector、Redis、一次性数据库迁移、FastAPI、Worker、
Next.js 和 Nginx。源码开发模式则只用 Compose 启动 PostgreSQL/Redis，其余进程在本机运行。

------------------------------------------------------------
一、开始前
------------------------------------------------------------

需要：

  - Docker Desktop 与 `docker compose`（全容器或依赖容器模式）；
  - uv 与项目支持的 Python 版本（本机运行后端、生成 Fernet 密钥或运行测试时）；
  - Node.js 与 npm（本机运行前端时）；
  - 可选：macOS、Edge 或 Chrome（仅现有 BOSS 标签页桥接）。

不要提交根目录 `.env`，也不要把 Key、Token、Cookie、浏览器 Profile 或完整代理 URL
粘贴到日志、截图或文档中。

------------------------------------------------------------
二、创建并检查配置
------------------------------------------------------------

根目录 `env_example` 是唯一的全量配置模板。新环境执行：

  test -f .env || cp env_example .env

然后在 `.env` 中填写相应服务的真实凭据；不要删除模板变量，用功能开关控制不使用的能力。
至少核对：

  - `POSTGRES_USER`、`POSTGRES_PASSWORD`、`POSTGRES_DB`、`POSTGRES_PORT`；
  - 本机源码模式使用的 `DATABASE_URL` 与上述数据库账号/密码一致；
  - `REDIS_PORT` 和 `REDIS_URL`；
  - API 与 Worker 共用的 `TASK_PAYLOAD_ENCRYPTION_KEY`；
  - 标准异步运行的 `TASK_QUEUE_ENABLED=true`；
  - 全容器模式的 `NEXT_PUBLIC_API_URL=/api`；
  - 所启用模型、Embedding、Langfuse、mem0 与评测功能所需的对应变量。

生成 Fernet 密钥：

  uv run --project backend python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

全容器模式会将 API 和 Worker 的数据库/Redis 地址覆盖为容器内服务地址，并将运行数据
挂载到 `/app/data`。不要手动把 `AUTO_CREATE_TABLES` 打开来替代迁移。

------------------------------------------------------------
三、全容器启动（推荐）
------------------------------------------------------------

在仓库根目录执行：

  mkdir -p nginx/logs
  docker compose --env-file .env config --quiet
  docker compose --env-file .env up -d --build

首次执行会构建 backend/frontend 镜像。`migrate` 是一次性服务，迁移成功后显示
`Exited (0)` 属于正常状态；其余服务应运行或通过 health check。

确认状态与服务：

  docker compose --env-file .env ps --all
  curl -fsS http://localhost/health
  docker compose --env-file .env exec backend python -m scripts.deployment readiness

浏览器入口与 API 文档：

  http://localhost
  http://localhost/api/docs

日常维护：

  # 实时查看关键日志
  docker compose --env-file .env logs -f migrate backend worker frontend nginx

  # 只重启 API 与 Worker
  docker compose --env-file .env restart backend worker

  # 停止服务但保留卷中的数据
  docker compose --env-file .env down

  # 删除容器卷中的本地数据：执行前确认无须保留 PostgreSQL 与 artifact 数据
  docker compose --env-file .env down -v

------------------------------------------------------------
四、源码开发启动
------------------------------------------------------------

此模式让 PostgreSQL 与 Redis 在容器中运行，后端、Worker 与前端在本机运行。
请先完成第二节的 `.env` 配置。

终端 1：启动依赖。

  docker compose --env-file .env up -d postgres redis

终端 2：初始化后端、迁移数据库并启动 FastAPI。

  cd backend
  uv sync
  uv run python -m scripts.deployment migrate
  uv run python -m scripts.deployment readiness
  uv run python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

本机 API 文档：

  http://localhost:8000/api/docs

终端 3：启动 Worker。标准配置 `TASK_QUEUE_ENABLED=true` 时必须保持此进程和 Redis 运行。

  cd backend
  ./scripts/run-worker.sh

终端 4：启动前端。保持 `.env` 中的 `/api` 供 Compose 使用，并仅为这一次本机 Next.js
进程覆盖 API 地址：

  cd web
  npm ci
  NEXT_PUBLIC_API_URL=http://localhost:8000 npm run dev

本机前端地址通常为：

  http://localhost:3000

后端启动会确保 `backend/data/`、`backend/data/artifacts/` 和 `backend/data/static/` 存在。
相对运行目录配置总是从 `backend/` 解析，不能依赖终端当前工作目录。

------------------------------------------------------------
五、首次进入后的模型配置
------------------------------------------------------------

在前端“设置 → 模型配置”中配置并验证至少一个 Smart 模型通道与一个 Fast 模型通道。
RAG、长期记忆、评测和 Langfuse 只在已配置其依赖与对应开关时使用；外部模型凭据不得
写入仓库配置或提交到 Git。

------------------------------------------------------------
六、macOS BOSS 现有标签页桥接（可选）
------------------------------------------------------------

这项能力只在 macOS 宿主机运行。它只访问用户已经打开的 Edge/Chrome 标签页；不创建
浏览器 profile、不读取 Cookie/Token/localStorage、不绕过登录、验证码或风控。真实外部
动作仍必须经过后端治理和用户确认。

1. 在浏览器中手动登录 BOSS 并完成验证码/安全验证，保留官方页面标签页。
2. 在“查看 → 开发人员”中启用 Apple 事件中的 JavaScript，并在 macOS“隐私与安全性 →
   自动化”中允许启动终端控制所选浏览器。
3. 另开终端启动宿主机服务：

     cd backend
     ./scripts/run-browser-automation-service.sh

   默认仅监听 `127.0.0.1:8765`，并且只清除该服务进程继承的代理变量。

4. 检查服务是否存活（不包含凭据或浏览器会话信息）：

     curl -fsS http://127.0.0.1:8765/

5. 在 `.env` 中设置不少于 32 字符的 `BROWSER_AUTOMATION_SERVICE_TOKEN`。
   主后端在 Docker 中运行时使用：

     BROWSER_AUTOMATION_SERVICE_URL=http://host.docker.internal:8765

   主后端也在宿主机运行时使用：

     BROWSER_AUTOMATION_SERVICE_URL=http://127.0.0.1:8765

不要将 8765 暴露到公网；如果本机 Docker 无法访问宿主机服务，应先检查 Docker Desktop
网络与防火墙配置，而不是放宽 Token 校验、复制 Cookie 或尝试绕过验证码。

------------------------------------------------------------
七、常见检查与排障
------------------------------------------------------------

  - 后端健康但 AgentRun 长时间排队：确认 Redis、Worker 与 `TASK_QUEUE_ENABLED=true`。
  - readiness 失败：先运行 `python -m scripts.deployment migrate`，再核对数据库地址、
    pgvector、迁移版本和 Embedding 向量维度；不要用 `create_all` 代替正式迁移。
  - 直接启动前端却请求到错误地址：使用
    `NEXT_PUBLIC_API_URL=http://localhost:8000 npm run dev`，不要修改容器模式的 `/api`。
  - 静态文件或 artifact 写入失败：检查 `backend/data/` 是否可写；不要在 `backend/app/`、
    `backend/ai/` 或其他源码包下创建运行数据目录。
  - Compose 端口冲突：先使用 `docker compose --env-file .env ps --all` 确认服务状态，
    再按需要调整模板中的公开端口；不要删除数据库卷来解决端口冲突。

可选质量检查：

  cd backend && uv run python -m scripts.static_quality governed
  cd web && npm run typecheck

停止本机源码进程时使用终端的 Ctrl-C；随后按需要执行：

  docker compose --env-file .env stop postgres redis
